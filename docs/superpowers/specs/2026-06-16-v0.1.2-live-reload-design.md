# v0.1.2 — Live-reload of rule files + redaction leak fix

Date: 2026-06-16
Status: approved design, pre-implementation
Milestone: v0.1.2 (distribution polish)
Branch: `feat/v0.1.2-live-reload`

## Problem

Two independent v0.1.2 issues, shipped together because they share `redact.yaml`
and the rule-loading path.

1. **Edits to rule files are silently ignored until restart.** Each addon loads
   its config once at construction and caches it in an instance field
   (`FingerprintAddon._rules`, `RedactAddon._patterns`, `EnforceAddon._policies`);
   `proxy._run()` builds the addons exactly once (`upbox/proxy.py:171`). The
   dashboard settings page writes the YAML and reports `saved to …`, but the
   running proxy — a separate OS process — never re-reads the file. The user's
   change does nothing until they rerun `upbox start`. For a privacy tool, "I
   tightened a redaction rule and it kept leaking" is a trust-eroding surprise.

2. **The Anthropic and OpenAI key-redaction patterns are broken.** `redact.yaml`
   ships `anthropic-key: sk-ant-[A-Za-z0-9-]{32,}` and
   `openai-key: sk-[A-Za-z0-9]{32,}`. Real modern keys use base64url
   (`sk-ant-api03-…` contains `_`; `sk-proj-…` / `sk-svcacct-…` contain `-`),
   so a realistic key does **not** match and is forwarded to the cloud
   **unredacted**. Verified empirically: `re.search(r"sk-ant-[A-Za-z0-9-]{32,}",
   "sk-ant-api03-aB3_dEf4-…")` returns `None`. This directly violates the tool's
   core promise ("secrets never reach the cloud LLM").

## Goals

- The running proxy applies edits to `tools.yaml`, `redact.yaml`, and
  `allowlist.yaml` automatically, with no restart, within ~1 second.
- A failed reload (bad YAML / bad regex) **keeps the previously-loaded config**
  and never crashes the proxy.
- Realistic Anthropic and OpenAI keys are redacted; coverage extends to Google,
  Slack, GitHub fine-grained / server tokens, and generic `Authorization: Bearer`.
- Zero new runtime dependencies.

## Non-goals (explicitly out of scope)

- **Reloading the TLS interception set (`allow_hosts`).** `tools.yaml` `hosts:`
  also feed mitmproxy's `allow_hosts`, which is frozen into `Options` at boot,
  upstream of all addons. Adding a brand-new host to intercept still requires a
  restart. This is documented, not silently broken. (Candidate for a later PR;
  mutating `master.options` mid-flight touches the live TLS engine and is higher
  risk.)
- **Dashboard-confirmed reload.** The proxy and dashboard share only SQLite + the
  rule files; a true "reload applied" confirmation needs cross-process state +
  polling. Out of scope. We surface reloads via a proxy log line and a copy tweak
  on the dashboard save message instead.
- **Debounce beyond failure-safe retry.** Atomic writes plus a reload that
  self-heals on the next mtime bump make an explicit debounce unnecessary.

## Design

### Approach (chosen: A)

Failure-safe **poll-watcher implemented as a mitmproxy lifecycle addon**, plus a
`reload()` method on each config-bearing addon, plus atomic writes from settings.
Rejected alternatives: launching the watcher task inside `proxy._run` (bleeds
lifecycle into `_run`); an inotify dependency (`watchfiles`/`watchdog`) — rejected
against the minimal-deps decision, since three `stat()`s per second is free.

Correctness rationale: mitmproxy runs a single asyncio event loop. Request hooks
and the watcher loop are coroutines on that one loop, scheduled cooperatively. A
reload only rebinds a config reference at an `await` point in the watcher; it can
never interleave inside a request hook. So a whole-reference rebind
(`self._patterns = new_list`) is atomic with respect to request handling — no
locks needed.

### Components

**1. Addon `reload()` methods** — `upbox/addons/{fingerprint,redact,enforce}.py`

Each addon gains:

```python
def reload(self) -> None:
    try:
        new = load_rules()          # or load_patterns() / load_policies()
    except Exception:
        log.exception("<kind> reload failed; keeping previous config")
        return
    self._rules = new
    log.info("reloaded tools.yaml (%d rules)", len(new))
```

The `load_*()` functions already exist and already fall back to bundled defaults
when no user file is present. `reload()` reuses them verbatim. On any exception
the cached field is left untouched (config is never blanked).

**2. `upbox/watch.py` (new)** — the watcher

- `async def watch_rules(targets: list[tuple[Path, Callable[[], None]]], poll_interval: float = 1.0) -> None`
  — polls each `(path, reload_fn)` pair. Tracks last-seen mtime per path.
  Treats a `None → mtime` transition (file created on first dashboard save) as a
  change. On change, calls `reload_fn()`. A `reload_fn` that raises is caught
  per-tick so the loop survives. Missing file → mtime `None` (no error).
- `class RuleReloadWatcher` — a mitmproxy addon. Its `running()` hook starts
  `watch_rules` via `asyncio.create_task` and attaches a done-callback that logs
  any unexpected task exception (per `error-handling.md`: no fire-and-forget).
  Its `done()` hook cancels the task. Constructed with the `targets` list.

The watched-path source of truth is each addon module's existing
`USER_RULES_PATH` constant — the watcher reuses those constants directly, so
there is one path constant per kind and no risk of the watcher and the loader
drifting apart. No new path-dedup, no `settings` import into the addons.

**3. Atomic writes** — `upbox/settings.py`

`validate_and_write()` currently does `user_path(kind).write_text(raw_text)`
(non-atomic). Change to: write to a temp file in the same directory, then
`os.replace(tmp, target)` (atomic rename on POSIX and Windows). Guarantees the
watcher never observes a half-written file.

**4. Wiring** — `upbox/proxy.py`

`_run()` already constructs the four addons. Bind them to names, build the
`targets` list from each addon's `USER_RULES_PATH` + its `reload`, construct
`RuleReloadWatcher(targets)`, and add it to the addon chain. No behavior change
to the existing addons' ordering.

**5. Redaction rules** — `upbox/rules/redact.yaml`

- Fix `anthropic-key` → tolerate base64url + prefix, e.g.
  `sk-ant-[A-Za-z0-9_-]{20,}`.
- Fix `openai-key` → match modern prefixes and base64url, e.g.
  `sk-(?:proj|svcacct|admin)?-?[A-Za-z0-9_-]{20,}` (final regex tuned in
  implementation against realistic samples; must match `sk-…`, `sk-proj-…`,
  `sk-svcacct-…` and not over-match ordinary `sk-` prose).
- Add: `google-api-key` (`AIza[0-9A-Za-z_-]{35}`), `slack-token`
  (`xox[baprs]-[0-9A-Za-z-]{10,}`), `github-fine-grained` (`github_pat_[0-9A-Za-z_]{22,}`),
  `github-server` (`ghs_[A-Za-z0-9]{36}`), and a generic bearer rule for
  `Authorization: Bearer <token>` in text bodies.

**6. Copy + docs**

- `upbox/dashboard/app.py` (settings save path): success copy notes the running
  proxy applies the change automatically within ~2s, no restart.
- `docs/redaction-rules.md`: replace the stale "restart … (live reload lands in
  v0.1.1)" line with text reflecting that rule edits now apply automatically as
  of v0.1.2 (new intercepted hosts still need a restart).
- `ROADMAP.md`: mark live-reload shipped in v0.1.2.
- `CHANGELOG.md`: v0.1.2 entry covering live-reload + the redaction fix
  (call out the leak honestly).

### Data flow

```
dashboard save → settings.validate_and_write() → os.replace() → file mtime bumps
   → watch_rules sees new mtime (≤ poll_interval) → addon.reload()
   → addon rebinds its config field → next request uses new config
```

No restart; no IPC beyond the file itself.

### Error handling

- Reload parse/compile failure → keep prior config, log, retry on next mtime
  bump (a transient mid-write read self-heals). Honors "addon failure must not
  crash the proxy."
- Watcher per-tick exceptions are caught; the task carries a done-callback that
  logs unexpected exits.
- `done()` cancels the watcher cleanly on proxy shutdown.

## Testing

All unit-level, on Linux, no live proxy. Mock only the filesystem boundary;
verify behavior, not mock calls. One assertion per test, AAA.

- **Reload (per addon):** rewrite a monkeypatched rule path A→B, call `reload()`,
  assert a flow now classifies/redacts/enforces per B. Plus: write uncompilable
  regex / garbage YAML, call `reload()`, assert the **pre-reload** config still
  applies (config not blanked).
- **Watcher (`test_watch.py`, real tmp files):** reload fires on mtime change;
  does not fire when unchanged; per-file isolation (edit one, only its reloader
  runs, asserted by effect); survives a raising reloader and still reloads on a
  later good edit; first-save (`None → mtime`) triggers a reload.
- **Settings atomicity:** after a write, no temp/partial file remains; an invalid
  write leaves any prior file byte-identical.
- **Redaction:** each realistic key (`sk-ant-api03-…`, `sk-proj-…`) is stripped;
  each new provider rule fires on a realistic sample; an ordinary `sk-` word in
  prose is not over-redacted.

Run after changes (file-scoped):
`uv run pytest tests/test_watch.py tests/test_fingerprint.py tests/test_redact.py tests/test_enforce.py tests/test_settings.py`,
then `uv run ruff check . && uv run ruff format . && uv run mypy upbox`.

The only thing not automated: end-to-end "edit file → live DumpMaster applies new
config" through LocalMode (needs root/iptables + a real upstream). It stays a
manual smoke check; each composed unit is proven separately.

## Risks

- **Regex over-matching** in the redaction fixes (e.g. a loose `openai-key`
  redacting ordinary text). Mitigated by realistic-sample tests including a
  negative case.
- **Poll latency** (~1s) is acceptable for a manual settings edit; matches the
  supervisor's existing poll idiom.
